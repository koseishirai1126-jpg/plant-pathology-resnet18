## 最初のモデルの方針（案）

- ImageNetで学習済みのResNet18を読み込み、最後の分類層を4クラス用に置き換えます。
- モデル全体を今回のデータで追加学習するファインチューニングを基本案とします。
- 入力画像は224×224ピクセルに前処理し、学習済み重みに対応する正規化を使います。
- CSVのラベルを確認し、1枚につき1クラスであることを検証してからCrossEntropyLossを使います。
- 学習時の出力は確率化する前の値（logits）を損失関数に渡し、予測時にsoftmaxで確率にします。
- 学習用と検証用はクラスの比率を保って分割し、同じ分割を再利用できるよう画像IDを保存します。
- 検証用画像はパラメータの更新に使わず、検証・テストにはランダムな画像変換を使いません。
- 検証では4クラスそれぞれのROC AUCと、その平均を記録します。
- 検証スコアが最も良い重みを保存し、テスト画像の予測に使います。
- 提出CSVの画像ID・行順・列順は、実データのsample_submission.csvに合わせます。

最初は1回の学習・1つのモデルで動作を理解することを重視します。
具体的な学習回数やバッチサイズは、計算環境を確認して決めます。

## 編集・実行の流れ

コードは手元のPCで編集し、GitHub経由で計算機に渡します。

1. 手元のPCでコードを編集する。
2. `git diff`で変更を確認する。
3. `git add`で履歴に含める変更を選び、`git commit`で手元に履歴を保存する。
4. `git push`でGitHubに履歴を送る。
5. 計算機では最初に`git clone`で取得したフォルダを`docker cp`でコンテナに渡す。以後はコンテナ内のリポジトリで`git pull --ff-only`してコードを更新する。
6. Dockerコンテナ内でコードを実行する。

Gitは手元の変更履歴を管理する道具、GitHubはその履歴をオンラインで共有するサービスです。
現在のコンテナには共有フォルダがないため、データの配置には`docker cp`を使います。
元データはGitHub経由ではなく、別途計算機に配置します。
