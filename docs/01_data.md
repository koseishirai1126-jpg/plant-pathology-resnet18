# 01: データと正解ラベルを確認する

## 使うファイル

公式のZIPを手元の`data/`に展開しました。ディレクトリ構成は次のとおりです。
元データはGitで管理せず、GitHubにも送信しません。

```text
data/
├── train.csv
├── test.csv
├── sample_submission.csv
└── images/
    ├── Train_0.jpg
    ├── ...
    ├── Test_0.jpg
    └── ...
```

| ファイル | 内容 | 行数（ヘッダーを除く） |
| --- | --- | ---: |
| train.csv | 学習用画像のIDと正解ラベル | 1,821 |
| test.csv | テスト用画像のID。正解ラベルは含まない | 1,821 |
| sample_submission.csv | 提出するCSVの形式の見本 | 1,821 |

`image_id`に`.jpg`を付けると画像のファイル名になります。
たとえば`Train_0`は`data/images/Train_0.jpg`に対応します。
大文字と小文字を含めて、CSVに書かれたIDをそのまま使います。

## 正解ラベルの読み方

`train.csv`の先頭は次のようになっています。

```csv
image_id,healthy,multiple_diseases,rust,scab
Train_0,0,0,0,1
Train_1,0,1,0,0
Train_2,1,0,0,0
```

| クラスの列名 | 意味 | 画像数 | コード内で使う予定のクラス番号 |
| --- | --- | ---: | ---: |
| healthy | 健康な葉 | 516 | 0 |
| multiple_diseases | 複数の病害がある葉 | 91 | 1 |
| rust | さび病の葉 | 622 | 2 |
| scab | 黒星病の葉 | 592 | 3 |

各行では4列のうち1つだけが1で、残りは0になっています。
この表現をone-hot（ワンホット）表現といいます。

たとえば`Train_0`のラベルは`[0, 0, 0, 1]`なので、クラスは`scab`です。
PyTorchの`CrossEntropyLoss`には、今回はこれをクラス番号`3`に変換して渡す方針です。
クラス番号は上の列順に対応させ、学習・検証・予測で統一します。

`multiple_diseases`も独立した1クラスです。
このデータでは、1枚の画像について4クラスのうち1つを予測します。

## 確認したこと（2026年11月6日）

- 学習用CSVのラベルはすべて0または1で、各行の合計は1でした。
- 学習用とテスト用を合わせた画像IDに重複はありませんでした。
- 全3,642件の画像IDに対応するJPGファイルが存在しました。
- `images/`にあるファイル数は3,642でした。
- 提出見本の画像IDと行順は`test.csv`と一致しました。
- `data/`内のファイルがGitの管理対象から外れることを確認しました。

ここでの画像の確認は、ファイルの存在と件数の確認です。
全画像の読み込み・表示の確認は、画像を読み込むコードを作る段階で行います。

## 学習用と検証用に分ける理由

学習用の1,821枚から、モデルのパラメータ更新に使う画像と、
未知の画像に対する性能の目安を測る検証用画像を分けます。
検証用画像はパラメータの更新に使いません。

`multiple_diseases`は91枚と少ないため、クラスの比率を保つ層化分割を使う方針です。
分割した画像IDを保存し、後輩と同じ検証データで比較できるようにします。
学習と検証を分けてから、学習側だけにランダムな画像変換を適用します。

テスト用画像の正解は配布されていないため、手元ではテストスコアを計算できません。
モデルで各クラスの確率を予測し、見本と同じ形式のCSVをKaggleに提出して評価します。
